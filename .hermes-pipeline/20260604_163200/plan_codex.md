## 5. Risks, Security, And Edge Cases

Risks:
- Existing `Button.tsx` already has an `lg` size, so this is a behavioral refinement rather than a new key. Tests should assert the intended class behavior to prevent regressions.
- `ProgressSteps` can become visually noisy on mobile if horizontal labels are long. Prefer responsive wrapping and vertical option.
- `FieldGroup` can create duplicate labels or IDs if callers misuse it; keep the API simple and document expected `htmlFor` usage through tests.

Security/HIPAA/multi-tenancy:
- These are presentational components only and must not read, fetch, store, log, or transform PHI.
- No Convex functions are touched, so tenant guards and billing invariants are unaffected.
- No route guards or auth flows are changed.
- Toast messages must be caller-provided; the primitive should not introduce logging or persistence of potentially sensitive text.

Edge cases:
- Missing optional `description`, `helperText`, `errorText`, or `action`.
- Icons should be decorative unless the visible title/message provides accessible meaning.
- Toast variant defaults should be deterministic, likely `info`.
- Progress state calculation should remain stable when `steps` order changes.
