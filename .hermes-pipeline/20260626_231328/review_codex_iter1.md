# ATRIA-X live Clerk/Convex E2E fix design doc

## Reproduction

Command:

```bash
npm run e2e
```

Environment:
- Clerk E2E users configured in `.env.local` / `C:\Users\pinol\.atriax\clerk-e2e.env`.
- Convex preview deployed at `https://admired-mink-447.convex.cloud`.

Observed failures after Convex deploy:
1. Clerk login with password-created API users can trigger Clerk's new-device email factor, so browser-password sign-in is not deterministic.
2. Deployed Convex initially lacked `seed:seedE2E` / `seed:resetE2EShifts`; deploying fixed that.
3. Geofence tests were stateful/flaky after the first scenario because the same deterministic shift IDs carried cached submitted/success-screen state.
4. Lifecycle test reached coordinator review but could time out on loading/filter state and proof-upload/autosave state.

## Root-cause analysis

The remaining issue is not missing Clerk credentials anymore. The root causes are:

- E2E fixture reset is not isolated strongly enough for a live Convex/browser run. Resetting the same existing shift documents in place leaves the browser/Convex client able to observe stale details for the same shift IDs after prior test scenarios.
- The tests depend on UI-driven geofence settings and role switching in the same page, which adds Clerk/Convex timing races.
- The live Clerk flow requires either real email factor handling or backend sign-in tickets for deterministic automation.

## Possible solutions

### Solution A: Keep reusing deterministic fixture rows and add waits/reloads

Pros:
- Smallest code diff.
- No backend fixture changes.

Cons:
- Still vulnerable to stale query cache for the same shift IDs.
- Requires scattered waits/reloads.
- Already showed inconsistent behavior across serial tests.

### Solution B: Make live E2E fixtures isolated per run/reset

Pros:
- Eliminates stale shift-detail cache by creating fresh shift documents for each reset/seed.
- Keeps tests representative of the real app while making fixture setup deterministic.
- Cleaner root-cause fix than adding waits everywhere.

Cons:
- Requires a conservative change in `convex/seed.ts` test fixture helpers and redeploy.

## Chosen solution

Solution B is the best fix: update E2E seed/reset behavior so each live E2E scenario starts from fresh fixture shift documents, while preserving the existing production app flow. Keep Clerk sign-in tickets for E2E auth only.
