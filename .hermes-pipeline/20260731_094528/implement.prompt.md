# Implementation Plan — Add "Home" navigation to the HR sidebar

## 1. Restated goal & acceptance criteria

**Goal:** HR users (and admins) must be able to click a persistent item in the left sidebar to navigate back to the HR landing page `/hr` after they have moved into a sub-section (Candidates, Employees, Cases, a candidate detail view, etc.).

**Key finding from the repo:** the sidebar (`src/app/shell/Sidebar.tsx`) *already* has a `/hr` entry, but it is mislabeled and mis-behaving relative to the committed spec:

- Line 94: `label: 'Home'` — but `src/app/shell/Sidebar.test.tsx` asserts the accessible link name is **`'HR Home'`** (`getByRole('link', { name: 'HR Home' })`). The current code makes those tests fail.
- Lines 93–98: the item has **no `exact: true`**, so with the existing `isActive` logic (`locationPath.startsWith('/hr/')`) it renders as *active* on `/hr/candidates`, `/hr/cases`, etc. The spec (`'marks HR Home active only on exact /hr'`) requires it to be active **only** on the exact `/hr` path.
- Line 96 uses `LayoutDashboard` (duplicating the Dashboard icon). The `Home` icon is already imported (line 16) but currently unused — which is also a latent `no-unused-vars` lint issue.

So this is a **conform-to-spec fix**, not a green-field feature. The `Sidebar.test.tsx` file is the acceptance contract.

**Acceptance criteria:**
1. A sidebar link with accessible name **"HR Home"** and `href="/hr"` is rendered for roles `org:admin` and `org:hr`.
2. It is **not** rendered for `org:coordinator`, `org:caregiver`, or any candidate role.
3. It is marked active (`bg-white/10 text-white`) **only** when the current path is exactly `/hr`; it is *not* active on `/hr/candidates`, `/hr/employees`, `/hr/cases`, or candidate detail routes.
4. Clicking it in the mobile drawer invokes `onMobileClose` (closes the drawer).
5. It uses the `Home` lucide icon (removes the unused-import smell and the icon collision with Dashboard).
6. Ordering: it appears above the other HR items (Candidates/Employees/Cases) so it reads as the section landing.
7. `npm run lint`, `npm run typecheck`, `npm run test` (Vitest) all pass; the full `Sidebar.test.tsx` suite is green; build succeeds.
